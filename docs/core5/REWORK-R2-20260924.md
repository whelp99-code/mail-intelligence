# Core5 재작업 R2 — 2026-09-24

## 현재 범위

미커밋 수정 후보다. 기존 운영 서비스·계정·메일·DB·개인 기억은 변경하지 않았다. 다른 에이전트/사용자의 기존 변경을 보존했다. 실제 CRM 또는 회사기억 연결 완료로 판정하지 않는다.

## 재현과 수정

`src/adapters/cwos-work-system.js`의 readMasters는 미연결일 때 정상 빈 목록을 반환했다. 빈 workspace, 다른 workspace 응답, 잘못된 응답도 그대로 통과했다. `test/core5-work-system-boundary.test.js`의 7개 사례 중 수정 전 4개가 실패했다. 원본을 다시 읽고 해시 전제조건을 고정한 제한 패치를 적용했다.

이제 미연결은 CWOS_CLIENT_UNAVAILABLE, 빈 workspace는 CWOS_WORKSPACE_REQUIRED, 잘못된 응답은 CWOS_RESPONSE_INVALID, 다른 workspace는 CWOS_RESPONSE_SCOPE_MISMATCH로 거부한다. 정상 0건과 정상 데이터는 보존하고 상위 오류를 다른 reader로 숨기지 않는다. write()와 회사기억 donor의 기존 권한 경계는 바꾸지 않았다. 응답의 workspace 일치 검사는 인증을 대체하지 않는다.

## 실제 제품 시험

새 helper `test/helpers/core5-isolated-product-server.js`는 실제 server.mjs를 별도 프로세스로 실행한다. 기존 환경변수와 운영 자격증명을 상속하지 않고 새 임시 DB·합성 계정·빈 저장소·발송 OFF를 사용한다. Graph 주소는 비활성 loopback 주소로 고정한다. 시험이 끝나면 자기 프로세스와 임시 DB만 정리한다.

`test/core5-product-http.test.js`는 실제 HTTP로 로그인, 초안 생성·재전송 중복 방지, 봇 승인 거부, CSRF/origin 거부, 발송 OFF, 사람 취소를 확인한다. 실제 제품을 재시작하고 취소 상태가 남는지 조회하며, 임시 SQLite를 읽기 전용으로 열어 취소 이벤트 1건·발송 이벤트 0건을 확인한다.

## 재현 명령 (이번 실행에서 통과)

Mail 프로젝트 루트에서:

```sh
node --test test/core5-work-system-boundary.test.js test/core5-product-http.test.js test/cwos-work-system.test.js test/mail-journey.test.js test/mail-send-api.test.js test/mail-send-drafts.test.js test/send-reconciliation-worker.test.js
git diff --check
```

결과: 32 passed / 0 failed / 0 skipped. HTTP 인수는 위 32개 중 1개이며 중복 집계하지 않는다. 이는 선택된 회귀시험이며 전체 npm test나 운영 수신·발송 시험은 아니다.

실제 화면 검사는 Shipping의 ci/core5/h03/run-product.mjs로 이 Mail helper를 호출한다. 기존 src/index.html·app.js·send-review.js와 실제 API를 사용하며 데모 Review 서버를 사용하지 않는다. 브라우저 3개 사례가 통과했고 실제 발송은 수행하지 않았다.
