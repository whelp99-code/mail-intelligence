# Mail Intelligence v1.2.1 — Official OAuth LLM Providers

## 1. 목적

Mail Intelligence의 사용하지 않는 `F-AIOS`, `LM Studio`, Gemini API-key 경로를 제거하고, 사용자가 이미 사용하는 공식 AI 계정의 OAuth 인증을 공식 CLI를 통해 안전하게 재사용한다.

이 버전의 목표는 브라우저 쿠키나 비공식 세션을 복제하는 것이 아니다.

```text
Mail Intelligence
→ official Codex/Grok CLI subprocess
→ official CLI-owned OAuth credential cache
→ structured analysis result
```

Mail Intelligence는 OAuth Access Token·Refresh Token을 읽거나 복사하거나 SQLite에 저장하지 않는다.

## 2. 범위

### 포함

- Rules Provider 유지
- OpenAI Codex CLI의 ChatGPT OAuth 상태 확인·분석 호출
- xAI Grok CLI의 OAuth 상태 확인·분석 호출
- CLI 설치·인증 상태 UI
- 로그인 명령 안내
- 실메일을 사용하지 않는 합성 연결 테스트
- 명시적 외부 AI 운영 게이트
- 메일 데이터 정책 동의
- JSON Schema·Message ID·원문 근거 검증
- OAuth Provider 실패의 투명한 표시
- Ubuntu user systemd 운영

### 제외

- ChatGPT/Grok 웹 브라우저 쿠키 재사용
- OAuth 토큰 직접 읽기·내보내기·DB 저장
- 비공식 OAuth client 구현
- Provider 간 자동 폴백
- Mail.Send·Mail.ReadWrite 활성화
- 자동 메일 발송·읽음 변경·이동·삭제
- Grok CLI 무인 설치
- 실제 운영 메일을 이용한 자동 외부 전송 테스트

## 3. Provider 계약

| ID | 공식 실행기 | 인증 | 기본 모델 |
|---|---|---|---|
| `rules` | 내장 규칙 | 불필요 | `rules` |
| `openai-codex-oauth` | `codex` | `codex login --device-auth` | 계정 기본 모델 자동 선택 |
| `xai-grok-oauth` | `grok` | `grok login --device-auth` | `grok-4.6` |

CLI OAuth 로그인과 credential refresh는 Mail Intelligence 서비스 사용자와 같은 Ubuntu 사용자 `jm`의 홈 디렉터리에서 수행한다.

## 4. 이중 승인

실제 메일 콘텐츠가 외부 LLM으로 전달되려면 다음이 모두 참이어야 한다.

```text
MAIL_INTELLIGENCE_ALLOW_EXTERNAL_AI=1
AND
aiProvider != rules
AND
aiOptInVersion == ai-oauth-opt-in-v1.2.1
AND
official CLI installed
AND
official CLI OAuth authenticated
```

운영자 게이트를 여는 명령:

```bash
npm run oauth:enable -- openai-codex-oauth
npm run oauth:enable -- xai-grok-oauth
```

이 명령은 Provider의 설치·OAuth 상태를 먼저 확인하고 외부 AI 게이트만 연다. 메일 변경 권한은 열지 않는다.

## 5. 실행 격리

### Codex

```text
empty 0700 temporary directory
--ephemeral
--ignore-rules
--ignore-user-config
--skip-git-repo-check
--sandbox read-only
--output-schema
--output-last-message
prompt via stdin
```

JSONL 이벤트에서 명령 실행, 파일 변경, MCP 도구 호출, Web Search, 이미지 생성이 감지되면 결과 전체를 거부한다.

### Grok

```text
empty 0700 temporary directory
--max-turns 1
--no-plan
--no-subagents
--no-memory
--disable-web-search
--disallowed-tools Bash, Read, Write, Edit, Glob, Grep, WebSearch, WebFetch, CodeExecution, ImageGeneration, Task, Skill
--output-format json
```

### 공통

- subprocess 환경변수 allowlist
- `OPENAI_API_KEY`, `XAI_API_KEY` 전달 금지
- stdout/stderr 각각 포함 전체 1 MiB 제한
- 실행 timeout 및 강제 종료
- 모델 식별자 allowlist 문자 검증
- 임시 디렉터리 종료 후 삭제
- 결과 Schema 검증
- 원문에 없는 Evidence 거부
- Provider 실패 시 Rules로만 degrade

## 6. 설정과 API

공개 설정:

```text
aiProvider
openaiCodexModel
xaiGrokModel
aiOptInVersion
```

저장하지 않는 값:

```text
ChatGPT OAuth token
xAI OAuth token
Codex credential JSON
Grok credential JSON
OPENAI_API_KEY
XAI_API_KEY
```

API:

```text
GET  /api/ai/oauth/status
GET  /api/ai/oauth/instructions?provider=...
POST /api/ai/oauth/test
```

모든 상세 API는 세션을 요구하며, POST는 기존 Origin·CSRF·mutation-protection 계약을 통과해야 한다.

## 7. 레거시 이관

다음 Provider는 v1.2.1에서 운영 선택지로 인정하지 않는다.

```text
f-aios-v3
lmstudio
gemini
```

저장된 레거시 Provider는 서버 시작 시 `rules`로 이관한다. 다음 레거시 필드는 제거하거나 새 요청에서 명시적으로 거부한다.

```text
geminiApiKey
geminiModel
faiosServerUrl
lmstudioServerUrl
lmstudioModel
```

## 9. 중단 조건

다음 중 하나가 발생하면 OAuth Provider 사용을 중단하고 Rules만 사용한다.

- 공식 CLI가 OAuth 대신 API-key 모드로 로그인됨
- 도구 실행 또는 파일 변경 이벤트 발생
- Evidence가 원문과 일치하지 않음
- 출력 Schema 위반
- credential cache 손상 또는 로그인 만료
- 외부 AI 운영 게이트 또는 UI 동의가 해제됨
- Provider 장애·timeout·출력 초과
