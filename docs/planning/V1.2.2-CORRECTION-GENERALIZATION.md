# Correction generalization

Owner approval on 2026-09-28 opened two gates that v1.2.2 had left closed: external AI classification, and applying a user correction to similar mail.

External AI still requires all of these. None of the guards were removed:

- `MAIL_INTELLIGENCE_ALLOW_EXTERNAL_AI=1`
- `aiOptInVersion == ai-oauth-opt-in-v1.2.2`
- selected provider is `openai-codex-oauth` or `xai-grok-oauth`
- the official CLI is installed and authenticated

LLM output is schema-checked. A citation that is not an exact span of the supplied mail is rejected and stored as a labeled rules fallback, not as an AI success. An explicit correction still outranks both the model and a learned policy.

A precision correction now also writes `message_feedback` and a versioned `precision_learning_policies` row. The policy matches later mail from the same sender when the conversation id matches or at least two subject-template tokens match. It does not match a different sender, and it does not overwrite a mail that already has its own correction. Applied rows use `source=hybrid` and `learned-policy:<id>` so they stay distinguishable from a direct user correction.
