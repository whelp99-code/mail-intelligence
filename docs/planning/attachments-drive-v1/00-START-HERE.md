# Mail Intelligence 파일 첨부·Google Drive 연동 개발계획

작성일: 2026-09-09 · 모드: PLAN-ONLY · 인계 대상: Cursor · 구현·커밋·배포 요청이 아닌 계획서 작성 결과.

## 목표와 문서 사용법

사람이 PC 파일 또는 Google Drive 파일을 선택하고, **실제로 발송될 파일의 고정된 사본**을 검토한 뒤 승인하면 기존 Outlook 발송 경로로 보내는 기능이다. 공유 링크만 보내는 모드도 명시적으로 제공한다. 파일 내용은 AI에 전송하지 않는다.

Cursor에는 `CURSOR-INSTRUCTIONS.md`를 먼저 전달한다. 이후 `01-DISCOVERY.md`, `02-REQUIREMENTS.md`, `03-CONTRACTS.md`, `04-RISKS-DECISIONS.md`, `05-IMPLEMENTATION.md`, `06-ACCEPTANCE.md`, 해당 `prs/` 카드를 읽는다. 단일 기능의 계획과 공통 계약을 함께 적용한다. 기존 문서는 대체하지 않고 이 디렉터리에 새 제안만 추가했다.

| 기능 | 사용자에게 보이는 결과 | 구현 카드 |
|---|---|---|
| F1 PC 파일 첨부 | 파일 선택·검사·목록·다운로드 검토·제거 후 새 초안 저장 | PR-001, PR-002 |
| F2 승인·안전 발송 | 파일 SHA-256까지 승인에 결합, 불일치 시 미발송, 발송된 첨부 검증 | PR-001, PR-002 |
| F3 Drive 공유 링크 | 링크로 보냄을 표시, 접근 가능 여부 미확인 경고, 자동 공개 금지 | PR-003 |
| F4 Drive 파일 첨부 | Google 계정 연결·Picker 선택·서버 사본 저장·실제 첨부 | PR-004 |
| F5 Google 문서 변환 | Docs/Sheets/Slides의 PDF 또는 Office 파일 변환 선택 | PR-004 |
| F6 Grok 명령 확장 | 파일·선택된 Drive ID로 초안 생성, 승인·발송 권한 없음 | PR-005 |
| F7 운영·복구 | 암호화 저장·보존·백업·복원·용량 한도·회귀 검증 | PR-002, PR-006 |
| F8 대용량 첨부 | 별도 승인 후 2 MiB 초과 upload-session 경로 | `07-LARGE-FILES.md` 조건부 후속 |

## 계획 범위와 기본값

아래는 ASSUMED 개발 기본값이며 사용자가 확정한 제품 한도가 아니다. 처음부터 구현 가능하게 정하되 실제 운영 활성화 전 소유자에게 확인한다. 크기 확대를 위해 승인·검증 게이트를 생략하지 않는다.

| 가정 | 기본값·이유 | 영향·되돌리기 |
|---|---|---|
| A1 소형 파일 우선 | 파일 하나와 메일 합계 각각 2,097,152 bytes, 최대 5개 | Graph JSON/base64 요청 크기를 보수적으로 관리; 확대는 후속 카드 |
| A2 업로드 형식 | PDF, DOCX, XLSX, PPTX, HWP, HWPX, TXT, CSV, PNG, JPEG | 실행 파일·매크로·암호화 문서는 차단; 지원 형식은 정책 버전으로 관리 |
| A3 Drive 권한 | Picker + `drive.file`, 제품 코드는 읽기 호출만 | 전체 Drive 검색 불가. 광범위 권한 자동 전환 금지 |
| A4 변환 기본 | Google 문서는 PDF, 사용자가 선택하면 DOCX/XLSX/PPTX | 렌더링 품질은 실파일 확인 전 미확인; 원본 링크 모드로 변경은 새 초안 |
| A5 사본 정책 | 선택 당시 bytes를 고정, 자동 최신 파일 교체 없음 | 원본 변경은 경고와 새 가져오기·재승인으로 처리 |
| A6 보존 | 미연결 자산 24시간 만료, 완료 파일 사본 30일 보존 제안, 정리는 기본 dry-run | 승인·sending 자산 자동 삭제 금지, 운영 보존정책 승인 없으면 삭제 미실행 |
| A7 저장·검사 | 소형 bytes는 SQLite 암호화 BLOB, 운영 첨부에는 로컬 악성코드 검사 성공 필요 | DB 성장·검사기 운영비 발생. 검사기 미구성은 첨부만 차단, 본문은 유지 |
| A8 운영 수치 | 동시 업로드/가져오기 2개, 미연결 자산 128 MiB/메일함, 전체 사본 512 MiB/메일함 | 실측 성능이 아닌 초기 제한. 초과429/507, 자동 용량확대 금지 |
| A9 승인 후 예외 | Drive 원본·권한 재확인 실패 시 미발송; 링크 수신권한은 미확인으로 표시 | 연결 장애 시 사본만 조용히 발송하지 않는다 |

이번 필수 범위는 F1~F7이다. 대용량, 임의 URL 다운로드, Drive 파일 수정·권한 부여, Gmail 발송, OCR·AI 문서 해석, 폴더 통째 첨부, ZIP 일반 업로드, inline CID 이미지, 자동·예약·일괄 발송은 기본 릴리스에서 제외한다. F8은 별도 실행 허가가 필요한 확장 설계이며 F1~F7의 완료를 대용량 지원으로 표현하지 않는다.

## 규모·권한

MUST 18개, 주 계획 6개 순차 카드, 예상 직접 변경·신규 파일 약 40~55개(기준선 보정 포함), migration 2개, 최고 초기 위험 R4. 따라서 XL 형식으로 문서를 분리했다. 마스터 스펙 파일이 이 환경에 없어 공개된 skill 템플릿의 전 항목을 본 세트에 대응시켰다. 첫 카드만이 아니라 모든 카드의 구현 단계를 명시하여 Cursor 인계성을 높였다.

한 Cursor 작업은 한 저장소를 변경한다. MI의 F1~F5/F7과 Gateway의 F6는 분리한다. Gateway는 통합 계약 소비자이지 MI 자격증명의 소유자가 아니다. 이 문서를 주었다는 사실만으로 고객 파일 외부 전송, Google 권한 확대, 운영 설치·배포·발송을 승인한 것으로 간주하지 않는다.

완료 판정은 코드 검증, 실제 승인 화면, Outlook 보낸 편지함, 본인 수신함의 첨부 bytes 일치를 포함한다. 계획서 승인과 구현 완료, 운영 배포는 서로 다른 상태다.
