- 상태: 구현 완료, Ubuntu 서비스 재시작 승인 대기
- 패키지 버전: `1.2.1`
- 분류기: `precision-classification-v1.2.1-qa-fix8`
- 검색기: `intelligent-search-v1.2.1-qa-fix8`
- 기준 독립 QA: qa-fix7 `NO-GO`

## 1. 문제 정의

qa-fix7은 Evidence, SQLite, Delta, 백업·복원, 재시작, 읽기 전용 안전선은 안정적이었지만 새 Blind 표본에서 의미 일반화에 실패했다.

```text
Main Blind Work State       66%
Main Blind Next Actor       70%
Main Blind Priority         76%
Important Action Miss       27.27%
Incident supplement State   60%
Incident supplement Actor   60%
검색 직접 관련              88%
```

주요 실패 유형:

```text
지원 요청·완료·외부 대기 경계
반송·입찰·비활성화·라이선스·장애 사건 누락
발신 전달 완료와 외부 회신 대기 혼동
자동 청구·세금계산서·카드 명세서 과상승
GPU 장애 Priority 하락
복합 검색의 무관 결과·무결과
```

## 2. 목표

상태 수를 늘리지 않고 현재 6개 상태의 의미 계약을 고정한다.

```text
ACTION_REQUIRED
WAITING
DECISION_REQUIRED
COMPLETED
REFERENCE
REVIEW_REQUIRED
```

목표는 특정 메일 제목이나 hash를 맞추는 것이 아니라 다음 순서로 일반화하는 것이다.

```text
현재 본문과 과거 이력 분리
→ lifecycle·방향·수신자 역할 판정
→ 현재 사건 추출
→ 사건 간 precedence 결정
→ Work State
→ Next Actor
→ Priority
→ Evidence exact span 검증
→ 충돌·근거 부족 시 REVIEW_REQUIRED
```

## 3. 고정 운영 정책

### 3.1 Lifecycle

```text
삭제·정크 폴더
→ 현재 Action 생성 금지
→ REFERENCE / NONE / LOW

최근의 불완전한 삭제 Draft
→ REVIEW_REQUIRED / UNKNOWN / NORMAL

현재 Draft의 실질 요청
→ 발송 대기 업무
→ WAITING / EXTERNAL_PARTY
```

삭제·정크 메일은 기록과 검색 이력으로는 보존하지만 현재 업무 Inbox로 다시 올리지 않는다.

### 3.2 방향과 다음 행동 주체

```text
내가 보낸 요청
→ WAITING / EXTERNAL_PARTY

내가 자료·답변만 전달
→ COMPLETED / NONE

내가 전달하고 상대 확인·회신을 요청
→ WAITING / EXTERNAL_PARTY

상대가 나에게 현재 행동을 요청
→ ACTION_REQUIRED / ME

상대가 외부 Support 주소에 요청하고 내가 참조됨
→ WAITING / EXTERNAL_PARTY
```

방향은 sender 하나만 보지 않고 sentitems 폴더, mailbox sender alias, 수신자 역할을 함께 사용한다.

### 3.3 Microsoft Graph Well-known Folder

다음 canonical ID를 직접 인식한다.

```text
sentitems
deleteditems
junkemail
```

표시명에 의존하지 않는다.

### 3.4 Support Lifecycle

```text
문제 해결·티켓 종료 통보
→ COMPLETED / NONE

티켓 종료 승인 요청
→ ACTION_REQUIRED / ME

상대가 지원 일정을 확정
→ WAITING / EXTERNAL_PARTY

지원팀이 추가 로그·조치를 요청
→ ACTION_REQUIRED / ME

파트너가 외부 Support 주소에 기술 조치를 요청
→ WAITING / EXTERNAL_PARTY

지원팀이 조사 중이며 추후 회신 예정
→ WAITING / EXTERNAL_PARTY
```

조건부 Footer는 상태를 만들지 않는다.

```text
추가 문의가 있으면 연락하십시오.
필요한 경우 회신해 주세요.
본 메일을 잘못 받았다면 삭제하십시오.
```

### 3.5 자동 알림과 업무 문서

```text
광고·뉴스레터·일반 인증번호
→ REFERENCE / NONE / LOW

청구서 준비·Bill36524 확인 완료
→ REFERENCE / NONE / LOW

신규 전자세금계산서 도착
→ REVIEW_REQUIRED / UNKNOWN / NORMAL

검수·승인·등록 처리 완료
→ COMPLETED / NONE / NORMAL

서비스 비활성화·구독 중지 예정
→ ACTION_REQUIRED / ME / NORMAL

카드·쿼터 한도 초과 위험
→ ACTION_REQUIRED / ME / HIGH

공유 폴더 이메일 인증 필요
→ ACTION_REQUIRED / ME / NORMAL
```

### 3.6 수신 산출물

```text
견적·제안·계약 문서만 도착
→ REVIEW_REQUIRED / UNKNOWN

견적과 함께 기술 제약·기능·구성 설명을 제공하고 후속 요청 없음
→ COMPLETED / NONE

장비 정보·라이선스 현황표·일반 자료
→ REFERENCE / NONE

문서 전달 후 현재 직접 검토·회신 요청
→ ACTION_REQUIRED / ME
```

### 3.7 Priority

HIGH 이상은 현재 본문의 검증 가능한 근거에만 연결한다.

```text
HIGH
- 현재의 긴급·즉시·금일·오늘·내일
- 48시간 이내 명시 기한
- 카드·쿼터 초과 위험
- 라이선스 invalid/expired로 현재 업무 중단 위험
- 현재 장애 조치 요청

CRITICAL
- 실제 서비스 중단
- 보안 침해·랜섬웨어·치명적 active incident
```

다음은 Priority 상승 근거가 아니다.

```text
Outlook importance 하나
과거 인용문의 긴급 표현
Disclaimer
문의 Footer
견적·계약이라는 단어
요청 문장 개수
Important Notice 문구만 존재
```

## 5. Evidence 계약

모든 자동 확정은 현재 canonical source의 exact span을 사용한다.

```text
sourceField
sourceMessageId
startOffset
endOffset
exactText
sourceHash
normalizationVersion=exact-source-span-v1
```

검증식:

```text
canonicalSource.slice(startOffset, endOffset) === exactText
sha256(canonicalSource) === sourceHash
```

과거 전달·인용 본문, UI placeholder, 생성 문장을 Evidence로 저장하지 않는다.

### 직접 근거 원칙

복합 Intent는 제목, bodyPreview, 현재 Work State Evidence 중 같은 필드에 필요한 의미가 함께 있어야 한다.

예:

```text
Sangfor IAG
→ 같은 현재 필드에 Sangfor + IAG

검토 필요한 세금계산서
→ REVIEW_REQUIRED + 제목/Evidence에 세금계산서 직접 근거

완료된 Sangfor 지원 문의
→ COMPLETED + Sangfor + support/ticket/case/지원/문의

대기 중인 라이선스 회신
→ WAITING + EXTERNAL_PARTY + license 직접 근거

Confluence 비활성화
→ ACTION_REQUIRED + ME + Confluence + deactivation 직접 근거
```

삭제·정크·광고는 검색 Top 결과에서 제외한다.

## 7. Ground Truth 충돌 거버넌스

기존 동결 라벨은 수정하지 않는다.

알려진 세트에는 다음처럼 제품 정책과 충돌하는 라벨이 존재한다.

```text
삭제 폴더의 메일을 현재 Action으로 라벨링
최근 삭제 Draft를 즉시 Low Reference로 라벨링
검증된 긴급 근거 없이 High 라벨링
완료된 구매 업무를 Low Reference로 라벨링
```

처리 원칙:

```text
라벨 변경 금지
충돌 숨김 금지
qa:ground-truth:policy-audit로 공개
충돌 세트는 report-only
새 Blind Holdout이 release-deciding gate
```

`qa-fix7 Main`과 `qa-fix5` 세트는 report-only다. Round3, qa-fix6, qa-fix7 incident는 회귀 게이트로 유지한다.
