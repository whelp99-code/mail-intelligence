# Mail Intelligence v1.2.1 qa-fix5 정확도 개선 설계

## 목적

독립 Round 3의 실패를 개별 제목·메일 ID 예외로 맞추지 않고, 다음 네 축을 하나의 고정 의사결정 순서로 통합한다.

1. 현재 본문과 인용·전달 이력
2. 수신·발신·Draft·삭제·정크 lifecycle
3. 전달된 산출물의 의미: 완료, 참고, 검토 필요, 직접 요청
4. 검증된 행동 근거와 실제 긴급도에 기반한 Priority

독립 Round 3 고정 50건은 알려진 회귀 벤치마크로 사용한다. 최종 독립 승인은 이 벤치마크뿐 아니라 코드 고정 후 새로 뽑은 비공개 holdout 50건을 함께 사용해야 한다.

## 상태 판정 우선순위

낮은 번호가 높은 우선순위다.

1. 불완전 Draft·빈 메시지
2. 삭제·정크 lifecycle 억제
3. 명시적 자동 완료
4. 보안 장비 인증·Alert 검토
5. 자동 전달된 거래 문서 검토
6. 일반 자동 알림·광고 억제
7. 수신 회신 본문의 직접 업데이트·직접 요청
8. 발신 요청의 외부 회신 대기
9. 발신 완료 산출물
10. 수신 산출물의 의미 분기
    - 작업 정상화·완료 결과: COMPLETED
    - 견적·제안·계약·발주 문서: REVIEW_REQUIRED
    - 장비 정보·현황표·일반 자료: REFERENCE
11. 근거 부족: REVIEW_REQUIRED

## Priority 계약

- HIGH는 명시적 긴급 표현, 현재 행동 근거의 48시간 이내 기한, 실제 원격 긴급 지원 요청에만 부여한다.
- Outlook importance=high 또는 요청 개수만으로 HIGH를 만들지 않는다.
- WAITING도 현재 본문 또는 제목에 명시적 긴급 표현이 있으면 HIGH를 유지한다.
- 자동 완료와 단순 시스템 알림은 LOW다.
- 일반 업무 Reference와 삭제 lifecycle 억제는 NORMAL을 유지한다.
- 보안 장비의 예상하지 못한 인증 Alert는 REVIEW_REQUIRED/HIGH로 보수적으로 올린다.

## 금지

- message ID/hash/특정 회사명을 분류 예외로 하드코딩하지 않는다.
- 독립 Ground Truth 라벨을 변경하지 않는다.
- 자동 테스트 PASS를 독립 승인으로 대체하지 않는다.
- Mail.Send, Mail.ReadWrite, Outlook 원본 변경을 활성화하지 않는다.
