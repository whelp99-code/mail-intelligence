## 2. 수정 범위

### 2.1 한국어 Outlook 회신 경계

다음 형식을 명시적 history boundary로 추가했다.

```text
2026년 ... 홍길동 <address@example.com>님이 작성:
... 님이 작성:
```

현재 본문만 다음 판단에 사용한다.

```text
Work State
Next Actor
Priority

Supporting Signals
Evidence
Search current context
```

운영 DB에서 `님이 작성:`이 있으면서 boundary가 `none`인 항목은 0건이다.

### 2.2 보낸 편지함 방향 판정

기존에는 mailbox address와 sender 비교만 사용했기 때문에 실제 보낸 메일이 수신 메일처럼 취급됐다.

모든 message read path에 folder metadata를 포함했다.

```text
folderName
folderWellKnownName
isOutgoing
isDeletedFolder
isDraftFolder
isJunkFolder
```

`보낸 편지함`, `Sent Items`, `Sent Mail`은 `isOutgoing=true`다.

분류 정책:

```text
보낸 명시적 요청
  → WAITING / EXTERNAL_PARTY

보낸 실질 업무 메일
  → WAITING / EXTERNAL_PARTY

보낸 자료·견적·발주 전달 후 확인 요청
  → WAITING / EXTERNAL_PARTY
```

운영 DB 최종 검증:

```text
Sent-folder ACTION/DECISION violations    0
Sent-folder WAITING actor violations      0
```

### 2.5 Actor 오탐 방지

Actor 탐지는 전체 메일의 임의 단어가 아니라 선택된 Work State Evidence를 우선 사용한다.

다음과 같은 수신 메일 호칭은 더 이상 내부 팀 Actor로 승격하지 않는다.

```text
대표님
팀장님
엔지니어님
```

수신된 구체 요청은 기본적으로 `ME`다.

### 2.6 Due·Signal·Priority 오염 방지

기존에는 긴 표·FAQ·계약기간의 모든 날짜와 단어가 Due·Security·Urgency로 오염될 수 있었다.

수정 후:

```text
Due
  → State Evidence 또는 마감·기한·납기·만료·일정 문맥만 사용

계약기간
  → Due 아님

가능한 빨리·조속히
  → ambiguous due 유지

Incident/Schedule/Approval
  → 제목, 본문 앞부분, State Evidence 중심

Priority
  → 현재 업무 Evidence 중심
```

예시:

```text
계약기간 2026-02-01 ~ 2027-01-31
  → Due 없음

FAQ의 장애 지원 내역
  → incident_security 아님

라이선스 2026-10-13 만료
  → Due 유지
```

기존 `발주서 → 서` 잔여 토큰 결함을 제거했다.

#### Prefix 검색

```text

```

#### 상태·관련성 정렬

```text

Action/Waiting/Decision/Completed 상태

Due
최신순
```

#### Garbage 억제

```text
삭제 폴더 제외
정크 폴더 제외
광고 제외
장애·보안 검색에서 세금계산서 폴더 제외
기한 검색에서 Reference·Completed 제외
```

#### 장애·보안 동의어

```text
장애
  → 장애, 오류, 중단, 접속불가, outage, incident

보안
  → 보안, security, VPN, 침해, 해킹
```

`계약완료`는 더 이상 완료 상태 필터로만 변환되지 않고 원문 합성어로 검색된다.
