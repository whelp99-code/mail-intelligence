## 1. 최종 결론

v1.0.1의 목적은 현재 프로토타입을 안전하고 정직하게 개발 가능한 읽기 전용 기준선으로 복구하는 것이다. 이번 작업에서 빌드 불가, 정적 분석, HTML/CSS 규칙, 개발 의존성 취약점, AI 응답 계약, 저장소 손상 처리와 릴리스 재현성 문제를 수정했다.

승인된 `ACCEPT-101`부터 `ACCEPT-105`까지의 엔지니어링 릴리스 게이트는 모두 통과했다.

```text
v1.0.1 엔지니어링 릴리스 게이트    PASS
v1.1.0 구현 착수                    GO
실제 Outlook read-only 운영 파일럿  NO-GO — live validation 미실행
외부 행동 활성화                    NO-GO — v2.0 action gate 전면 유지
운영 배포                           NO-GO — 별도 운영 승인 필요
```

실제 Outlook 계정이나 실제 AI Provider를 사용하지 않았으므로 이 결과는 운영 파일럿 승인이 아니라 **코드·보안·패키지 기준선의 통과**를 의미한다.

## 2. 정정 및 복구 이력

이전 작업 중 `server.mjs`와 `src/app.js`에 중복 선언과 누락 헬퍼가 발생해 서버가 기동되지 않았고, 당시 완료 보고는 취소됐다.

복구 순서:

```text
실패 재현
→ 중복 선언 및 누락 서버 헬퍼 복구
→ 세션·CSRF·Host·Secret 경계 복원
→ AI Provider·재시도·폴백 복구
→ 저장소 손상 fail-closed 복구
→ 정적 분석 도구 설치 후 실제 오류 수정
→ 개발 의존성 high 취약점 제거
→ clean npm ci
→ 전체 릴리스 게이트
→ fresh-extract 패키지 재검증
```

## 3. 해결한 주요 문제

### 3.1 서버·프론트엔드 빌드 오류

- `server.mjs`의 중복 `fetchWithTimeout` 제거
- `src/app.js`의 중복 `safeExternalUrl` 제거
- 누락된 JSON 응답, 보안 헤더, 세션, CSRF, Body parser, Host 검증 헬퍼 복원
- 사용하지 않는 import·변수 제거
- 들여쓰기와 문자열 규칙 정리
- 제어문자 검사를 `no-control-regex`에 의존하지 않는 명시적 코드포인트 검사로 변경

### 3.2 읽기 전용 안전 경계

Microsoft Graph delegated scope:

```text
openid profile offline_access User.Read Mail.Read
```

기본 상태에서 다음 외부 변경은 모두 차단한다.

- 메일 발송·답장·전달
- 읽음·안 읽음 변경
- 이동·삭제·카테고리·플래그 변경
- 일정·업무·CRM·프로젝트 변경
- Data Plane 전송

외부 행동 API는 세션과 보호 헤더가 있어도 `403 EXTERNAL_ACTION_DISABLED`로 실패한다. 메일 본문의 prompt injection이 허용되지 않은 도구 실행 액션으로 승격되지 않는 회귀 테스트도 추가했다.

### 3.3 로컬/API 보안

- `127.0.0.1`, `localhost`, `::1`만 허용
- 비루프백 Listen Host 차단
- Host header 검증
- HttpOnly·SameSite=Strict 세션
- Origin·CSRF 또는 mutation protection 검증
- JSON Content-Type 및 object 강제
- 요청 본문 256 KiB 제한
- CSP, COOP, CORP, Permissions Policy
- 정적 경로 traversal, 잘못된 인코딩, 외부 symlink 차단
- Outlook 외부 링크 HTTPS 제한
- OAuth 오류 HTML escaping

### 3.4 Secret과 손상 데이터

접근키 운영 모드에서는 다음 값을 AES-256-GCM으로 암호화할 수 있다.

- Outlook Access Token
- OAuth Refresh Token
- Microsoft Client Secret
- Gemini API Key
- Token 만료 시각

공개 설정, 암호화 Secret, 메일 캐시는 owner-only 경로와 원자적 rename으로 저장한다. 다음 손상 상황은 모두 원본을 보존하며 fail-closed한다.

- 공개 설정 JSON 손상
- 암호화 Secret envelope 손상
- 메일 캐시 손상

### 3.5 AI 분석 계약

- 일반 JSON과 fenced JSON 파싱
- 응답 크기 512 KiB 제한
- Message ID 누락·중복·미지 값 거부
- 상태·신뢰도·요약·근거·액션 schema 검증
- 원문에 없는 근거 거부
- `done`, `reference` 상태의 외부 행동 제안 금지
- 허용되지 않은 tool/action type 거부
- Provider·Model·Pipeline·메일 revision 기반 캐시
- 요청 Provider와 실제 Provider 분리 표시
- F-AIOS 일시 오류 재시도
- F-AIOS 실패 시 LM Studio 폴백 및 원인 기록
- Circuit Breaker 검증

통합 경로는 loopback mock으로 검증했다.

```text
Mock Microsoft Graph
→ Mail Intelligence 수집
→ Mock F-AIOS 분석
→ 엄격 schema/evidence 검증
→ API 결과 반환
```

```text
Mock F-AIOS 2회 실패
→ Mock LM Studio 폴백
→ requestedProvider=f-aios-v3
→ provider=lmstudio
→ 시도 이력과 폴백 원인 확인
```

실제 F-AIOS, LM Studio, Gemini 운영 서버 UAT는 별도 운영 파일럿 항목이다.

### 3.6 분류 정합성

- 과거 완료 표현보다 현재 긴급 재작업 요청 우선
- 회신 불필요 뉴스레터를 `reference`로 분류
- 모든 메일에 3개 회신안을 강제하지 않음
- 인용된 과거 요청을 현재 업무로 중복 생성하지 않음
- `importance=high`만으로 no-action 메일을 긴급 처리하지 않음
- 범용 Core에 Sangfor 제안을 자동 주입하지 않음
- `done/reference` 사용자 보정 후 task/action/calendar/reminder 동시 제거
