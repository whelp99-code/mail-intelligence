## 2. qa-fix7에서 해결한 영역

### 의미 분류

- 지원 티켓 종료, 종료 승인, 일정 확정, 조사 중, 외부 Support 요청을 분리했다.
- 반송, 입찰 마감, 서비스 비활성화, 카드 한도, 공유 폴더 인증을 의미 사건으로 처리했다.
- 수신 견적·제안·계약 문서의 검토와 상세 답변 완료를 구분했다.
- 자동 청구서·세금계산서·구매 포털 완료를 분리했다.
- 세무 가이드·총정리의 D-day와 질문형 마케팅 문구가 Action을 만들지 않도록 했다.
- 현재 본문과 전달·인용 이력을 계속 분리했다.
- Graph canonical folder ID `sentitems`, `deleteditems`, `junkemail`을 전 경로에서 인식한다.
- Lifecycle 및 Draft 정책을 semantic event보다 우선한다.

### Priority

- 현재 본문의 검증 가능한 긴급·기한·장애 근거만 High/Critical에 사용한다.
- Footer, Disclaimer, Outlook importance, 과거 인용 표현, 문장 개수를 Priority 근거에서 제외한다.
- 서비스 비활성화는 명시적 즉시 기한이 없으면 Normal이다.

## 11. 운영 배포 상태

운영 SQLite 데이터는 qa-fix8로 재분류됐지만, systemd 프로세스는 qa-fix8 코드 변경 이후 재시작되지 않았다.

확인한 기존 서비스 시작 시각:

```text
mail-intelligence.service          2026-09-01 14:50:34 KST
mail-intelligence-tailnet.service  2026-09-01 13:50:16 KST
NRestarts                           0 / 0
```

`/api/health`에 다음 실행 코드 버전을 추가했다.

```text
precisionClassificationVersion
intelligentSearchVersion
```

현재 live 검증은 기존 프로세스에서 이 필드가 없어서 의도대로 실패한다.

```text
npm run verify:live:local
→ FAIL
→ actual undefined
→ expected precision-classification-v1.2.1-qa-fix8
```

이는 코드 결함이 아니라 **qa-fix8 프로세스 재시작이 아직 수행되지 않았다는 직접 증거**다.

도구에서 다음 작업은 별도 명시적 승인 대상으로 차단됐다.

```text
systemctl --user daemon-reload
systemctl --user restart mail-intelligence.service
systemctl --user restart mail-intelligence-tailnet.service
```

따라서 다음 항목은 아직 PASS로 기록하지 않는다.

```text
qa-fix8 live process version
qa-fix8 local live deployment
qa-fix8 Tailnet live deployment
qa-fix8 live Delta 2회
qa-fix8 live restart persistence
qa-fix8 31분 안정성
```
