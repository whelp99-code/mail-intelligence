# Mail Intelligence v1.2.1 qa-fix5 정확도 개선·구축 보고서

## 1. 목적과 기준

qa-fix5는 기능 수를 늘리는 작업이 아니라 독립 Round 3에서 실패한 실제 메일 분류 정확도를 높이는 작업이다.

Round 3의 핵심 실패는 다음이었다.

```text
Work State                 35/50 = 70%
Next Actor                 37/50 = 74%
Priority                   31/50 = 62%
Reference false-action      2/50 = 4%
Important miss              1/13 = 7.7%
Evidence exact             100%
동일 검색 질의             10/10 PASS
```

Round 3 보고서가 제시한 최소 수정 방향대로 현재/인용 문맥, 발신 lifecycle, 산출물 전달, 직접 요청을 하나의 precedence 구조로 통합하고 Priority를 검증 가능한 긴급도에만 연결했다.

## 2. 구현

### 2.1 명시적 상태 판정 순서

분류기는 다음 순서를 사용한다.

```text
1. incomplete draft
2. deleted/junk lifecycle
3. automatic completion
4. security verification alert
5. automated business document
6. low-value automatic reference
7. incoming inline response
8. informational update
9. forwarded mail without a current request
10. queued outbound request
11. outgoing delivery completion
12. outgoing request
13. outgoing incomplete message
14. outgoing substantive message
15. incoming delivery
16. base-state classifier
```

특정 회사명, 제목, message ID 또는 hash를 분류 예외로 하드코딩하지 않았다.

### 2.2 Draft와 불완전 메일

```text
빈 Draft                 REVIEW_REQUIRED / UNKNOWN / NORMAL
인사말·서명만 Draft       REVIEW_REQUIRED / UNKNOWN / NORMAL
삭제된 의미 있는 Draft    REFERENCE / NONE
발송 대기 요청 Draft       WAITING / EXTERNAL_PARTY
```

빈 초안을 정상 Reference로 숨기지 않고 검토 대상으로 남긴다.

### 2.3 수신 산출물 의미 분리

```text
작업 정상화·완료 결과      COMPLETED / NONE
견적·제안·계약·발주 문서   REVIEW_REQUIRED / UNKNOWN
장비 정보·현황표·일반 자료 REFERENCE / NONE
직접 확인·검토 요청 포함   ACTION_REQUIRED / ME
```

메일에 파일을 전달했다는 이유만으로 모두 Completed로 처리하지 않는다.

### 2.4 보안·자동 문서

```text
일반 계정 인증번호        REFERENCE / NONE / LOW
Sangfor 등 보안장비 Alert  REVIEW_REQUIRED / UNKNOWN / HIGH
자동 Ecount 발주 문서      REVIEW_REQUIRED / UNKNOWN / NORMAL
일반 자동 알림·광고       REFERENCE / NONE / LOW
```

### 2.5 Priority 계약

HIGH는 다음의 검증 가능한 근거가 있을 때만 부여한다.

```text
명시적 긴급 표현
48시간 이내의 현재 업무 기한
실제 원격지원 escalation
보안장비 인증 Alert
```

다음만으로 HIGH를 만들지 않는다.

```text
Outlook importance=high 하나
요청 문장 여러 개
견적·계약·발주 키워드 하나
인용된 과거 긴급 표현
```

WAITING 메일도 현재 제목·본문에 명시적 긴급 표현이 있으면 HIGH를 유지한다.

## 3. 알려진 독립 Ground Truth 회귀 고정

Round 3에서 사용한 실제 50건의 hash와 기존 기대 라벨을 변경 없이 다음 파일로 고정했다.

```text
test/fixtures/aside-round3-fixed-50.json
```

파일에는 메일 제목·본문·발신자·자격증명이 없고 다음 정보만 포함한다.

```text
12자리 message hash
expected Work State
expected Next Actor
expected Priority
Reference 여부
Important 여부
```

실행 명령:

```bash
npm run evaluate:independent:round3
```

평가기는 SQLite에 저장된 과거 결과를 그대로 읽지 않고 현재 qa-fix5 소스에서 원문 50건을 다시 계산한다.

```text
evaluationMode   recomputed-from-source
classifier       precision-classification-v1.2.1-qa-fix5
evaluationNow    2026-08-31T03:00:00.000Z
```

qa-fix5 결과:

```text
found                       50/50
Work State                  50/50 = 100%
Next Actor                  50/50 = 100%
Priority                    50/50 = 100%
Reference false-action      0/50 = 0%
Important miss              0/13 = 0%
Mismatches                  0
Verdict                     GO_CANDIDATE
```

이 결과는 알려진 회귀 집합의 복구 증거다. 개발 중 사용된 표본이므로 이것만으로 독립 GO를 선언하지 않는다.

## 4. 새 Blind Holdout 준비

알려진 50건을 완전히 제외한 새 50건의 owner-only 템플릿을 생성했다.

```text
path          data/qa/qa-fix5-blind-holdout-template.json
benchmarkId   qa-fix5-blind-175e85180953
permissions   0600
mail content  없음
predictions   없음
known hashes  50건 전부 제외
```

표집 구성:

```text
draft                   4
lifecycle               3
automated               8
outgoing                8
forwarded_or_replied     8
incident_or_security     5
business_document       7
general_inbound         7
합계                    50
```

이 템플릿은 Aside가 시스템 결과를 보기 전에 원문으로 라벨링하고 SHA-256을 고정한 뒤 평가한다. 검토용 `qa:holdout:inspect`는 현재 분류를 출력하지 않고, `qa:holdout:finalize`는 50건의 라벨 완결성을 검증해 동결 파일을 생성한다.

```bash
npm run qa:holdout:inspect -- --index 1
npm run qa:holdout:finalize -- \
  --input data/qa/qa-fix5-blind-holdout-template.json \
  --output data/qa/qa-fix5-blind-holdout-labels.json \
  --reviewer aside-independent-round4
```

동결 이후에만 다음 명령으로 현재 소스를 재계산해 채점한다.

```bash
npm run evaluate:independent -- \
  --labels data/qa/qa-fix5-blind-holdout-labels.json \
  --recompute
```

## 9. 호스트 유지보수 참고

이전 원격 검증 호출이 502 또는 timeout으로 끊기면서 `chatgpt2codex.service` 아래에 제품 서비스가 아닌 테스트·배포 검증 프로세스가 남아 있다. 제품의 두 systemd 서비스는 정상이며 이번 검증은 private TMPDIR로 별도 완료됐다.

남은 검증 프로세스 종료는 프로세스 kill에 대한 명시적 승인 게이트가 필요하다. 이를 제품 정확도·데이터 무결성 PASS와 혼동하지 않는다.
