# Mail Intelligence v1.2.2 — Layout & Design Stabilization

## 1. 입력 증적

독립 레이아웃 점검은 `http://localhost:3010/`의 1512 × 872 CSS px 데스크톱 뷰포트를 기준으로 수행됐다. 점검 결과는 기능 가용 여부와 별개로 데스크톱 핵심 업무 레이아웃을 `FAIL`로 판정했다.

핵심 문제:

1. `.mail-shell`의 실제 자식은 `목록 / 리사이저 / 상세 / 리사이저 / Action`의 5개인데 Grid는 3개 열만 선언했다.
2. Action 열과 두 번째 리사이저가 다음 행으로 내려갔다.
3. 핵심 메일 업무 영역은 초기 뷰포트 하단에 일부만 보였다.
4. 설정 확장 시 인증, AI Provider, 초안 성격이 동시에 펼쳐져 업무 화면을 밀어냈다.
5. 상단 연결 상태와 설정 요약 상태가 서로 다른 문구를 표시할 수 있었다.
6. 1180px 이하에서 리사이저가 독립 Grid 행으로 남을 수 있었다.

## 2. 적용 범위

이번 수정은 분류 엔진, Outlook Delta, SQLite schema, 검색 의미 모델, 외부 행동 안전선은 변경하지 않는다. 다음 UI 계약만 수정한다.

- 핵심 업무 화면 우선 배치
- 5개 Grid track 명시
- 데스크톱 3패널 동행 배치
- 리사이저 접근성과 반응형 격리
- 설정 영역 분리 및 내부 스크롤
- 연결 상태 단일 렌더러
- 상단 상태·검색·가져오기 밀도 축소

## 3. P0 — 5 Track Mail Workspace

데스크톱 `.mail-shell`은 다음 구조를 고정한다.

```text
메일 목록 | 6px 리사이저 | 메일 상세 | 6px 리사이저 | Action/일정/알림
```

CSS 계약:

```css
.mail-shell {
  grid-template-columns:
    minmax(240px, var(--mail-list-width)) 6px
    minmax(320px, var(--mail-detail-width)) 6px
    minmax(280px, var(--mail-action-width));
}
```

리사이저는 일반 패널로 취급하지 않고 고정 6px track을 사용한다. 마우스 드래그와 좌우 화살표 키를 지원하며, 더블 클릭 시 기본 비율로 복구한다.

## 4. 첫 화면 우선순위

DOM의 주요 순서를 다음으로 바꿨다.

```text
상단 검색·동기화
읽기 전용 안전 알림
메일 목록 → 상세 → 다음 행동
정밀 분류·운영 Lane 상세
SQLite 운영 상태
연결·분석 설정
```

메일 업무 영역은 초기 뷰포트에서 바로 시작하며, 보조 KPI와 설정은 아래쪽에 둔다. 데스크톱 높이는 남은 뷰포트에 맞춰 `clamp()`로 제한한다.

## 5. 설정 패널 분리

한 개의 긴 설정 Grid를 다음 네 섹션으로 나눴다.

1. **Outlook 인증** — 기본 열림, Login Tenant·Client ID·Mailbox·로그인 버튼만 우선 표시
2. **고급 Outlook 인증** — 기본 접힘
3. **AI Provider** — 기본 접힘
4. **초안 작성 성격** — 기본 접힘

외부 설정 패널이 열려도 내부 내용은 최대 `min(68vh, 620px)`에서 스크롤한다. 업무 화면 전체를 무제한으로 아래로 밀지 않는다.

## 6. 연결 상태 단일 Source

`connectionStatus`와 설정 summary의 `configStatus`는 `updateOutlookConnectionStatus()` 하나로 렌더링한다.

상태 계약:

```text
미연결
설정 저장 중
Microsoft 승인 대기
연결됨
SQLite 오프라인 캐시
Callback/Token 교환 오류
```

OAuth 팝업이 localhost callback으로 돌아오면 성공·실패 본문을 확인한 뒤 상태를 다시 불러온다. 이전 성공 문구와 신규 실패 문구가 동시에 남지 않는다.

## 7. 상단 밀도

- 제목 영역과 조작 영역을 2열 Grid로 고정한다.
- 검색, 메일 수, 가져오기를 데스크톱 한 줄 우선으로 배치한다.
- 긴 Delta 상세는 한 줄 ellipsis로 표시하고 전체 문구는 `title`로 유지한다.
- main/sidebar padding과 section gap을 줄였다.

## 8. 반응형 계약

`width <= 1180px`에서는:

```text
메일 목록
메일 상세
Action / 일정 / 알림
```

순서로 한 열에 쌓는다.

- `.col-resizer { display: none; }`
- 6px 리사이저 전용 행 생성 금지
- 설정 내부 Grid 한 열
- 상단 조작부 줄바꿈 허용
- 안전 알림 문구 줄바꿈 허용

## 9. 회귀 검증

신규 `test/layout-contract.test.js`가 다음을 고정한다.

- Mail workspace가 Precision·Storage·Settings보다 먼저 위치
- 데스크톱 5-track Grid
- 리사이저 2개와 separator 접근성
- 오래된 inline `gridTemplateColumns` 리사이즈 재도입 금지
- 설정 4개 섹션과 기본 열림 1개
- 설정 내부 max-height/scroll
- 1180px 이하 리사이저 숨김
- 연결 상태 단일 렌더러
- OAuth pending/success/failure 상태 경로

## 10. 수용 기준

1512 × 872에서:

- 목록·상세·Action의 상단 Y 좌표 차이 2px 이하
- 리사이저 두 개가 같은 행과 높이를 공유
- Action 열이 다음 Grid 행으로 이동하지 않음
- Mail workspace 상단이 초기 viewport 안에 존재
- 설정은 기본 접힘

설정 확장 시:

- Outlook 인증만 기본 열림
- AI Provider와 초안 성격은 접힘
- 설정 내용이 지정 max-height를 초과하면 내부 scroll

1180px 이하에서:

- 리사이저 computed display=`none`
- 패널은 목록 → 상세 → Action 순서
- 6px 빈 행 없음
