# Mail Intelligence v1.2.2 — Microsoft OAuth localhost Redirect Fix

## 1. 문제

Microsoft Entra App Registration에는 다음 Redirect URI가 등록되어 있다.

```text
http://localhost:3010/auth/callback
```

기존 구현은 OAuth 시작 요청을 받은 HTTP `Host` 헤더에서 Redirect URI를 동적으로 생성했다. 따라서 브라우저가 `localhost`가 아닌 `127.0.0.1`, Tailnet 주소 또는 다른 허용 Host로 접근하면 Microsoft authorization 요청에 서로 다른 `redirect_uri`가 포함될 수 있었다.

대표 실패값:

```text
http://127.0.0.1:3010/auth/callback
```

Microsoft Entra는 등록된 Redirect URI와 요청의 `redirect_uri`를 정확히 비교하므로 이 동작은 `AADSTS50011`을 발생시켰다.

## 2. 수정 계약

v1.2.2의 Outlook Delegated OAuth Redirect URI를 다음 값으로 고정한다.

```text
http://localhost:3010/auth/callback
```

다음 값에서 Redirect URI를 파생하지 않는다.

- Backend bind 주소
- 요청 `Host` 헤더
- 브라우저가 사용한 접속 주소
- Tailnet IP
- SSH 터널의 원격 대상 주소

Backend는 보안 경계를 유지하기 위해 계속 `127.0.0.1:3010`에만 바인딩한다. 사용자는 SSH 터널을 연 뒤 브라우저에서 `http://localhost:3010`으로 접속한다.

## 3. 구현

`server.mjs`에 단일 상수를 두고 authorization 요청과 authorization-code 교환이 같은 값을 사용하도록 했다.

```text
OUTLOOK_OAUTH_REDIRECT_URI=http://localhost:3010/auth/callback
```

OAuth 시작 시 이 값을 pending PKCE state에 저장한다. Microsoft token endpoint의 code exchange에서도 저장된 동일 값을 다시 사용한다.

공개 Health에는 비밀값이 아닌 운영 계약 필드만 추가했다.

```text
outlookOAuthRedirectUri=http://localhost:3010/auth/callback
```

이를 통해 Local 및 Tailnet Live 검증이 실행 중 프로세스의 실제 OAuth 계약을 확인한다.

## 4. 안전성 유지

수정하지 않은 경계:

```text
Graph delegated scope:
openid profile offline_access User.Read Mail.Read

금지:
Mail.Send
Mail.ReadWrite
메일 발송·답장·전달
읽음 변경
이동·삭제·Flag·Category 변경
Calendar·CRM·Data Plane 쓰기
```

Azure에 `https://127.0.0.1`, Tailnet IP 또는 추가 Redirect URI를 등록하지 않는다.

## 5. 회귀 검증

다음 검증을 추가하거나 강화했다.

- 임의의 `127.0.0.1:<test-port>` Host로 서버를 호출해도 authorization URL은 정확히 `localhost:3010`을 사용한다.
- GET OAuth 시작 경로와 UI가 사용하는 POST OAuth 시작 경로를 모두 검사한다.
- `redirect_uri`에 `127.0.0.1`이 포함되지 않는지 검사한다.
- authorization scope에 `Mail.Read`가 있고 `Mail.Send`가 없는지 검사한다.
- Local Live와 Tailnet Live의 Health가 고정 Redirect URI를 보고하는지 검사한다.
- 정적 Safety Gate가 Host-derived `redirectUri(req)` 구현의 재도입을 차단한다.

## 6. 사용자 재시도

기존 Microsoft 로그인 오류 창은 잘못된 authorization 요청으로 이미 생성되었으므로 닫는다. SSH 터널을 유지한 상태에서 새 브라우저 탭으로 다음 주소를 연다.

```text
http://localhost:3010
```

그 후 `Outlook으로 로그인`을 다시 눌러 새 authorization 요청을 시작한다.
